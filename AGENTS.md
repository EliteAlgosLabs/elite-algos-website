# Working on this repository

Everything above this line is generated by `next dev` and will be rewritten.
Everything below is hand-maintained — edit it freely.

Read this before your first change. It is short, and every item on it is
something that has already caused a build failure or would silently ship a bug.

## Before you start

```bash
npm install
npm run verify      # typecheck + lint + build. Run this before every commit.
```

`npm run verify` is the same gate CI runs. If it passes locally, CI passes.

You need Node **20.9+** (the repo pins 24 in `.nvmrc`). Next.js 16 refuses to
build on Node 18.

## The five traps

**1. `middleware.ts` does not exist — it is `src/proxy.ts`.**
Renamed in Next 16. The named export must be `proxy`. The edge runtime is not
supported there; it always runs on Node.

**2. `params`, `cookies()`, `headers()` are Promises.**
The Next 15 synchronous shim is gone. `const { locale } = await params`.
`PageProps<'/[locale]/…'>` and `LayoutProps<…>` are *global* types — do not
import them, and run `npx next typegen` if your editor cannot find them.

**3. Adding a string in English but not French breaks the build.**
`src/lib/i18n/dictionaries/en.ts` is the type source; `fr.ts` is typed as
`Dictionary`. This is deliberate — it is the mechanism that keeps the two
languages in step. Add the key to `en.ts` first, then translate in `fr.ts`.
Note `en.ts` has **no `as const`**; adding one would force French to be
character-identical to English.

**4. Never import a data module from a page.**
Pages read content through `content` (`src/lib/content/repository.ts`),
submissions through `submissions` (`src/lib/contact/store.ts`), users through
`users` (`src/lib/auth/users.ts`). Each is an interface with one implementation
and one swap point. Importing `data/portfolio.ts` directly in a page defeats the
whole arrangement and makes the eventual database migration a rewrite.

**5. Auth is enforced on the server, in every page.**
`await requirePermission('viewAnalytics', locale)` at the top of the module.
The sidebar hiding a link is a courtesy, not a control — a user who types the
URL must still be stopped.

## Rules that are not negotiable

**Do not invent data.** No fabricated case studies, no placeholder people, no
plausible-looking metrics in dashboard modules that have no data source. Use
`—`. This is documented in
`company-brain/02-Engineering/Decisions/ADR-004-No-Fabricated-Content.md` and it
exists because invented numbers get screenshotted into decks and become claims
the company has to defend.

**Do not commit secrets.** `.env*` is git-ignored except `.env.example`, which
must keep its values empty. Secrets are runtime environment variables — never
build args (those survive in Docker image history) and never `NEXT_PUBLIC_`
(that ships them to the browser).

**Do not use raw colour values.** Components use `bg-background`, `text-muted`,
`border-border`. The palette primitives live in `@theme` in
`src/app/globals.css`; the semantic layer maps them per theme. Reaching past it
produces a component that looks right in light mode and unreadable in dark.

**Animate only `opacity` and `transform`,** and make sure
`prefers-reduced-motion` lands on the *final* state, never on hidden.

## Where things live

| You want to change | Edit |
|---|---|
| Any visible text | `src/lib/i18n/dictionaries/{en,fr}.ts` |
| Services / solutions / case studies / articles | `src/lib/content/data/` |
| Colours, type scale, motion curves | `src/app/globals.css` (`@theme`) |
| Who can do what in the dashboard | `src/lib/auth/rbac.ts` (matrix screen is generated from it) |
| Logo geometry | `src/lib/brand.ts` — **measured values, do not round them** |
| Deployment | `docs/deployment.md`, `Dockerfile`, `deploy/nginx/` |

## Known open items

These are deliberate V1 boundaries, each marked in the code:

- Contact submissions are **in-memory** and lost on restart —
  `src/lib/contact/store.ts`. Add an email adapter before relying on the inbox.
- Portfolio case studies are **samples** flagged `sample: true`. Replace them
  and delete the flag; all warnings clear automatically.
- No Content-Security-Policy — needs a per-request nonce, tracked in
  `docs/deployment.md` §10.
- Contact rate limiting and login throttling are per-process; they must move to
  Redis before running more than one replica.
